# gkmSVM-R tutorial

This is the tutorial from <https://www.beerlab.org/gkmsvm/gkmsvm-tutorial.htm>, updated for the
current version of the package. The workflow, the input files and the commands are the same; the
notes marked **(0.90)** describe what changed and how to reproduce the results of the version used
in the papers ([v0.80](https://github.com/mghandi/gkmSVM/releases/tag/v0.80)) exactly.

`tutorials/run_tutorial.R` runs everything below unattended (it downloads the input files) and
prints the AUROC/AUPRC and the top-scoring 10-mers; it is what was used to test this page.

## Installation (Linux or macOS, R ≥ 4.1)

The package itself only needs CRAN packages. The Bioconductor genome packages are needed for
`genNullSeqs` (generating the matched negative set) only.

```r
$ R
> install.packages(c('ROCR', 'kernlab', 'seqinr'))
> if (!requireNamespace("BiocManager", quietly = TRUE)) install.packages("BiocManager")
> BiocManager::install(c('GenomicRanges', 'rtracklayer', 'BSgenome',
+                        'BSgenome.Hsapiens.UCSC.hg38.masked'))   # add 'BSgenome.Hsapiens.UCSC.hg19.masked' etc. as needed
> quit()
```

**(0.90)** The original page had `install.packages('ROCR','kernlab','seqinr')`, which installs only
`ROCR` (the other two names land in the `lib` and `repos` arguments); use the vector form above.

If you want to use the mm10 mouse genome, the Bioconductor `BSgenome.Mmusculus.UCSC.mm10.masked`
lacks the repeat masks (`RM`, `TRF`) that `genNullSeqs` uses; install the repeat-masked build instead:

```r
> install.packages('remotes')
> BiocManager::install('BSgenome.Mmusculus.UCSC.mm10')
> remotes::install_github('mbeer3/BSgenome.Mmusculus.UCSC.mm10.masked')
```

Then the package:

```
$ git clone https://github.com/mghandi/gkmSVM.git
$ R CMD INSTALL gkmSVM
```

(`R CMD INSTALL` no longer requires the Bioconductor packages to be present.) The standalone
command-line binaries can be built from the same tree with `make` (see the top-level `Makefile`).

## Running gkmSVM-R on a CTCF ChIP-seq set (human, hg38)

Similar to Ghandi, Lee, Mohammad-Noori & Beer, *PLoS Comput Biol* 2014. Input files, from
<https://www.beerlab.org/gkmsvm/downloads/> (use "Save link as…"):
`CTCF_GM12878_hg38_top5k.bed`, `nr10mers.fa`, `ref.fa`, `alt.fa`.

### 1. Generate a GC-, length- and repeat-matched negative set and extract the sequences

Larger negative sets can be generated by increasing `xfold`; running time can be decreased by
reducing `nMaxTrials`, at the cost of not matching difficult sequences. In general, training on
larger sequence sets produces more accurate and robust models.

```r
$ R
> library(gkmSVM)
> library(BSgenome.Hsapiens.UCSC.hg38.masked)
> genNullSeqs('CTCF_GM12878_hg38_top5k.bed', nMaxTrials=10, xfold=1,
+             genome=BSgenome.Hsapiens.UCSC.hg38.masked,
+             outputPosFastaFN='CTCF_GM12878_hg38_top5k.fa',
+             outputBedFN='neg1x_CTCF_GM12878_hg38_top5k.bed',
+             outputNegFastaFN='neg1x_CTCF_GM12878_hg38_top5k.fa')
```

### 2. Calculate the kernel matrix

```r
> gkmsvm_kernel('CTCF_GM12878_hg38_top5k.fa', 'neg1x_CTCF_GM12878_hg38_top5k.fa',
+               'CTCF_GM12878_vs_neg1x_kernel.out')
```

**(0.90)** The kernel values are identical to v0.80's, to the last printed digit. Two things are
new: the computation uses all cores by default (`nmaxThreads=`), and a small sidecar
`CTCF_GM12878_vs_neg1x_kernel.out.index` records which sequence each row belongs to. Use
`format = "binary"` to write the kernel in the compact `.gkmk` format instead of text (about 3x
smaller, far faster to load; the training functions read both).

### 3. Train the SVM with cross-validation

```r
> gkmsvm_trainCV('CTCF_GM12878_vs_neg1x_kernel.out', 'CTCF_GM12878_hg38_top5k.fa',
+                'neg1x_CTCF_GM12878_hg38_top5k.fa', svmfnprfx='CTCF_GM12878_vs_neg1x',
+                outputCVpredfn='CTCF_GM12878_vs_neg1x_cvpred.out',
+                outputROCfn='CTCF_GM12878_vs_neg1x_roc.out')
```

This should give AUROC ≈ 0.965 and AUPRC ≈ 0.964, with some small variation arising from the
randomly sampled negative set. The model is written as `CTCF_GM12878_vs_neg1x_svalpha.out` and
`CTCF_GM12878_vs_neg1x_svseq.fa`, exactly as before, plus **(0.90)** a single-file model
`CTCF_GM12878_vs_neg1x.gkmmodel` that also carries the SVM bias.

### 4. Generate 10-mer weights

```r
> gkmsvm_classify('nr10mers.fa', svmfnprfx='CTCF_GM12878_vs_neg1x', 'CTCF_GM12878_vs_neg1x_weights.out')
```

**(0.90) — reproducing the v0.80 numbers.** Two things differ from v0.80 in the scores (not in the
ranking): the scores are now consistently normalised (v0.80 normalised the test sequence over all
mismatch levels while the score itself only counted up to `maxnmm`; fixed in this version), and
when the `.gkmmodel` file exists `gkmsvm_classify` subtracts the SVM bias. To get the same
numbers as v0.80, use the legacy normalisation and point at the legacy model pair:

```r
> gkmsvm_classify('nr10mers.fa', svmfnprfx='CTCF_GM12878_vs_neg1x', 'CTCF_GM12878_vs_neg1x_weights.out',
+                 legacyNorm=TRUE,
+                 svseqfile='CTCF_GM12878_vs_neg1x_svseq.fa', alphafile='CTCF_GM12878_vs_neg1x_svalpha.out')
```

`legacyNorm=TRUE` alone reproduces the old normalisation; naming the two legacy files skips the
bias, which is a constant shift. Both are also available on the command line (`gkmsvm_classify -y`).

You can then select the top weights in Unix with

```
$ sort -grk 2 CTCF_GM12878_vs_neg1x_weights.out | head -12
```

or from within R with

```r
> wts <- read.table('CTCF_GM12878_vs_neg1x_weights.out')
> wts[order(wts$V2, decreasing=TRUE)[1:12], ]
```

which should give weights very similar to:

### 5. Score the impact of a variant

To calculate the impact of a variant, here on CTCF binding, `gkmsvm_delta` scores the two alleles
given in FASTA format in `ref.fa` and `alt.fa` and reports the difference. This differs only by a
scale factor from deltaSVM calculated directly from the SVM weights, as described in Lee, Gorkin,
Baker, Strober, Asoni, McCallion & Beer, *Nature Genetics* 2015.

```r
> gkmsvm_delta('ref.fa', 'alt.fa', svmfnprfx='CTCF_GM12878_vs_neg1x', 'dsvm_CTCF_GM12878_vs_neg1x.out')
```

**(0.90)** The bias cancels in the difference, so only `legacyNorm=TRUE` is needed to match v0.80
here (`gkmsvm_delta` passes it on to `gkmsvm_classify`).

## The same for the mm10 mouse genome

Input file: `CTCF_MEL_mm10_top5k.bed`. Use the repeat-masked mm10 build from the installation notes.

```r
> library(gkmSVM)
> library(BSgenome.Mmusculus.UCSC.mm10.masked)
> genNullSeqs('CTCF_MEL_mm10_top5k.bed', nMaxTrials=10, xfold=1, genome=BSgenome.Mmusculus.UCSC.mm10.masked,
+             outputPosFastaFN='CTCF_MEL_mm10_top5k.fa', outputBedFN='neg1x_CTCF_MEL_mm10_top5k.bed',
+             outputNegFastaFN='neg1x_CTCF_MEL_mm10_top5k.fa')
> gkmsvm_kernel('CTCF_MEL_mm10_top5k.fa', 'neg1x_CTCF_MEL_mm10_top5k.fa', 'CTCF_MEL_vs_neg1x_kernel.out')
> gkmsvm_trainCV('CTCF_MEL_vs_neg1x_kernel.out', 'CTCF_MEL_mm10_top5k.fa', 'neg1x_CTCF_MEL_mm10_top5k.fa',
+                svmfnprfx='CTCF_MEL_vs_neg1x', outputCVpredfn='CTCF_MEL_vs_neg1x_cvpred.out',
+                outputROCfn='CTCF_MEL_vs_neg1x_roc.out')
> gkmsvm_classify('nr10mers.fa', svmfnprfx='CTCF_MEL_vs_neg1x', 'CTCF_MEL_vs_neg1x_weights.out')
> wts <- read.table('CTCF_MEL_vs_neg1x_weights.out'); wts[order(wts$V2, decreasing=TRUE)[1:12], ]
```

This should have AUROC around 0.97 and give high scores to k-mers similar to the human model's, as
CTCF binding specificity is conserved between human and mouse.

## Test run (2026-08-29, macOS, 20 cores, version 0.90.0)

`run_tutorial.R` on the human data, with `set.seed(1)`:

| step | result | time |
|---|---|---|
| `genNullSeqs` | 5 000 positives, 4 728 matched negatives | 119 s |
| `gkmsvm_kernel` | 9 728 × 9 728 lower triangle, 587 MB text | 50 s |
| `gkmsvm_trainCV` | **AUROC 0.964, AUPRC 0.963** (page: 0.965 / 0.964); 5 727 support vectors | 92 s |
| `gkmsvm_classify` on the 524 800 10-mers | default and v0.80-compatible modes, 24 s each |
| `gkmsvm_delta` | 579 variants, deltaSVM −7.9 … 7.4 | |

Top 10-mers in the v0.80-compatible mode: `CCACTAGGGG 6.859`, `CCACCAGGGG 6.695`, `CCACTAGAGG 6.460`,
`CACCTAGTGG 6.187`, `CACCTGGTGG 6.133`, `CACCAGGGGG 5.907`, `CACTAGGGGG 5.828`, `CACTAGAGGG 5.756`,
`CACCAGGTGG 5.637`, `CCACCAGAGG 5.512`, `CACTAGGTGG 5.433`, `CACCAGAGGG 5.311` — eleven of the twelve
k-mers on the original page, with values within a few percent (the negative set is sampled). The
default mode ranks them the same (Spearman 0.99999 over all 10-mers) with values about 14 % lower,
which is the normalisation change plus the bias.

Reproduction check: the v0.80 package, run on the *same* model files, produced 10-mer weights
**byte-identical** to the `legacyNorm=TRUE` output above, and deltaSVM values equal to the printed
precision (max difference 1e-6).

## Other things that are new in 0.90

* `gkmsvm_train(..., backend = "libsvm")` trains with the LIBSVM solver embedded in the package
  (no kernlab needed); the standalone `gkmsvm_train` binary does the same.
* Alphabets other than DNA: `alphabetFN = "protein"`, `"rna"`, or a file listing the symbols.
* Duplicate sequence names no longer stop the R functions; rows are identified by position.
* Very large sets: `gkmsvm_kernel(..., tileRows = )` bounds the memory of the kernel computation.

See `NEWS.md` for the full list.
